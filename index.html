Cash is a file.

Forward it. The first open spends it.

ZCrypt is a shielded chain you can use without a centralized exchange. Every coin of every asset sits in one pool. Anyone can issue an asset into it, exchange it inside the protocol, and hand the result to someone as a text file. The chain never learns who paid, which asset moved, or how much.

01 — 06 What the chain is

01

One pool.
Every coin, every asset.

There is no transparent transfer. A coin exists only as a hiding commitment in one global pool, and it moves by one shielded spend. Nobody can opt out of privacy on a transfer, so nobody fragments the anonymity set. An asset you issue sits in the same pool as ZCRYPT, under the same proofs and the same rules.

A zBTC transfer and a ZCRYPT transfer are indistinguishable on the wire.

02

A spend hides among
every coin ever made.

Most privacy coins sample decoys: your spend hides in a ring of eleven or sixteen, and intersection analysis erodes that over time. ZCrypt does not sample. The spend circuit carries a Merkle path from the spent commitment to a recent root of the global tree, so the anonymity set of every spend is the whole history of the pool.

A one-input spend is padded with a phantom coin. Arity is invisible.

03

A bearer coin
is a text file.

Send it the way you send a photo. The receiver drops it on their wallet and the value is credited. No address, no prior balance: the file carries the fee that spends it. The chain learns that two coins exist and, later, that someone swept them. It does not learn who handed the file to whom.

zcrypt-bearer.txt
zcrypt-bearer/1
coin zcb1q8f3l…m7d2kx0v
gas  zcb1zr9ap…4hqn6te8

The file is the money until it is claimed. The first sweep takes it.

04

The exchange
is the chain.

Two people agree on a trade. Each locks what they offer, under one shared secret. Revealing the secret settles both sides together; if the clock runs out, each side takes its own coins back. One side can be ZCRYPT, the other any asset anyone has issued. No order book to host, no router, no listing that can be pulled.

Bitcoin comes in as zBTC through an in-consensus SPV light client.

05

Built to outlive
the quantum computer.

A spend is not a signature. It is knowledge of a secret, proved inside a STARK: hash functions all the way down, no trusted setup, no elliptic curve under the coin. Notes are encrypted to ML-KEM-768 keys, so a ciphertext recorded today stays closed later. Issuance authorities sign with ML-DSA.

Zero signatures in the value layer. Poseidon2 over BabyBear.

06

Hidden payments.
A public rulebook.

Every kind of transaction has one short program. The shielded payment's is seven lines, and the proof is a proof that this program passed. The wallet runs the plain program before it broadcasts and refuses to send if it disagrees with the circuit. The no-inflation rule is a theorem in Lean, accepted with no holes.

  1. CHECK_RANGE
  2. CHECK_SINGLE_ASSET
  3. CHECK_CONSERVATION
  4. COMPUTE_NULLIFIERS
  5. COMPUTE_OUTPUTS
  6. CHECK_MEMBERSHIP
  7. HALT

Open any transaction in the explorer and you get the program, step by step.

Issue an asset into the pool

Register a ticker, a precision, and a supply cap. From then on the asset is minted, sent, swapped, and turned into a bearer file under the same rules as ZCRYPT. The identifier sits inside the coin, hidden. Minting more needs an ML-DSA authorization over that exact mint.

Selective disclosure, not backdoors

A view key is the decryption key with no spend secret. Hand it to an auditor and they see the value, blind, and asset of each incoming coin on one address class. They cannot spend, cannot see whether a coin was later spent, and cannot see stealth, change, or bearer activity.

Machine-checked conservation

A payment the rules accept never pays out more than it took in, and the field arithmetic inside the proof cannot wrap into a new coin. Both are theorems in Lean. The boundary of what is and is not proved is written down with the proofs.

Download First session

Checking the public release.

    1. 1
      Install and open the wallet. Mac: open the disk image. Windows: run the setup. Linux: mark the AppImage executable, or install the deb.
    2. 2
      Point it at the live chain. Settings → Consensus Node → https://rpc.zcrypt.network. The first node you connect defines the chain your signatures bind to.
    3. 3
      Tor is on by default. The wallet will not talk to the node unless a Tor daemon is on 127.0.0.1:9050. Turn it off for a first session on a clear network.
    4. 4
      Receive needs no prior balance. Someone pays you or sends a bearer file, and Refresh credits the coins. Spending inside the pool burns 0.01 ZCRYPT as gas.

    Mac images are Developer ID signed, notarized, and stapled. The Windows installer is not Authenticode-signed, so SmartScreen can warn. Source build instructions are in the developer docs.
